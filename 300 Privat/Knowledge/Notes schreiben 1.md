> Beim erstellen einer Notiz ist meist die Größte Blockade die Frage *Wo fange ich an?*
> Diese Note erklärt wie ein sogenannter Hook das Problem löst.


# Der Hook
## Was ist ein Hook
Eine gute Note startet immer mit einem Hook, welcher den Leser sofort informiert um was die Note handelt.
Die Frage welche ein Hook dem Leser beantwortet ist:
**Ist diese Note relevant für mich?**

## Wann welche Hook
Es ist wichtig beim erstellen einer Hook immer die Frage zu stellen *Wer ist mein Publikum für diese Note*?
Werde ich selbst diese Note einmal lesen um mich wieder an das Thema zu erinnern?
Oder handelt es sich um ein Bericht bei welchem man am Anfang schnell wissen muss um was es geht?
Wenn die Note jemandem etwas erklären soll, dann sollte die Hook die Frage sein welche geklärt wird. 
Wenn es eine Dokumentation ist, dann soll die Hook einem den Überblick verschaffen was Dokumentiert wurde.

| Note-Typ             | Hook-Form       | Beispiel                                      |
| -------------------- | --------------- | --------------------------------------------- |
| Wissen / Konzept     | Frage           | _"Wie funktionieren Transaktionen in T-SQL?"_ |
| Projekt / Bericht    | Zusammenfassung | _"Kontext · Problem · Ergebnis"_              |
| Workflow / Anleitung | Ziel-Satz       | _"Diese Note beschreibt wie man X macht"_     |
| Daily / Log          | Datum + Fokus   | _"Patchday 2026-06-11 — Fokus: WSUS01"_       |

# Inhalt
Nachdem eine gute Hook die Note startet ist es wichtig, dass es da nicht aufhört.
Beim schreiben des Inhalts stellt man sich nach jedem Abschnitt die Frage *Versteht das eine Person ohne Vorwissen?* 
Um das zu gewährleisten sollte beim schreiben angenommen werden, dass die Person welche diese Note liest in den seltensten Fällen irgendwelche Abkürzungen oder Vorwissen besitzt.
Dadurch entstehen natürlich wieder neue Abschnitte mit Erklärungen, *aber ist das wirklich nützlich?*
## Weniger ist mehr
Wenn man nach diesem Prinzip geht kommt es schnell einmal vor, dass die Note sehr lange wird, da man alles erklären muss.
Das Problem dabei ist, dass desto länger die Note wird desto weniger verständlich wird diese.

Obsidian bietet da aber eine Elegante Lösung:
*Warum nicht daraus eine neue Note erstellen und referenzieren?*

Daher lieber 2 Notes schreiben anstelle einer langen Note bei welcher man den Überblick verliert.
